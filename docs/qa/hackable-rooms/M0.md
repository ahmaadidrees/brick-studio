# Hackable rooms M0: the groundwork, November 3, 2026

The owner said "Yes, start M0". This is the groundwork from `README.md` that kids don't see. Nothing changes in a
single-player game, and nothing is wired into the studio or the Worker yet. That is M1.

**Branch:** `claude/hackable-rooms`, committed locally and not pushed or deployed.

## What's done

| Piece | Where | What it does |
|---|---|---|
| **Game state lives in the world** | `core/contracts.ts`, `platformer.ts`, `race.ts`, `looks.ts`, `runtime.ts` | State is saved with the world instead of in module WeakMaps. **World:** `everyTick`, `nextThreadId`, `toldBumps` (by target id). **Each target:** `bubbleId`, `lastHit`, `wasOnGround`, `lap`. Clones still start without these, as before. Race caches are keyed by `world.bricks` and the grid, so copies share them and a brick edit (a new `bricks` object) refreshes them. |
| **Saving a running game** | `core/snapshot.ts` | `copyWorld` (for rewind; shares bricks and script blocks). `worldToJson` / `worldFromJson` (for keyframes; keeps Infinity, NaN and −0, which plain JSON loses). `worldFingerprint`, a 32-bit hash over every world field except bricks and grid; numbers hashed by their bits, every NaN alike. |
| **Players** | `core/players.ts`, `runtime.pressKey/releaseKey(key, player?)`, `sensing.ts` | `world.players` keeps each player's keys. `addPlayer`: the first player takes the painted Hero, later players get a copy 20 steps to the side, started like the rest if the game is running. `removePlayer`: takes their Hero, clones and keys. A Hero (and its clones) hears only its player's keys; bricks that are no one's hear everyone's. Keys from someone not in the game are ignored. |
| **Rewind** | `rooms/timeline.ts` | `HackableTimeline`, the twin of the classic `Timeline`. Own events apply at once and are confirmed, moved or refused by the room. Late events rewind to the newest copy before them and replay. A copy is kept every 4 ticks for 300 ticks. Sounds from replayed ticks are dropped. Too-old events return false, so the caller asks for a keyframe. |

## Decisions taken in M0 (worth a look)

- **"key pressed?" on a brick that belongs to no one hears any player's keys.** The Bounce brick reads `space`
  pressed, so it now bounces higher if anyone holds space. A "my player" idea for non-Hero bricks, such as "the player
  touching me", belongs with the M1/M2 blocks.
- **"Play again" in a room** (the sync test's `playAgain`): a fresh game from the edited project, the same players in
  the same order, added before the green flag, still holding their keys. M1's room will do the same.
- **A brick edit replaces `world.bricks` with a new object.** It must never change it in place, because caches and
  copies rely on that.

## Not done (M1 and later)

- **Not wired in:** the studio's Play, the camera, the HUD and the Worker don't know about players. `Stage.tsx` still
  drives one keyboard.
- **No new blocks yet:** "when a player joins", player name and count, "for each player" variables. They need editor
  work.
- **Copies:** Racing's copy still includes its ~1,000 unchanging track cells (about 3 ms; every 4 ticks for now).
- **Not tried:** Firefox (needs `npx playwright install firefox`, which downloads it), real iPads and Chromebooks, and
  kids' own class projects.
