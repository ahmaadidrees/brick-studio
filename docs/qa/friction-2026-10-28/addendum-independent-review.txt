RECOMMENDED ADDITIONS
Paths below are relative to the checkout above. Sizes are estimates, not commitments.

1. MUST: cyclic broadcasts bypass the runtime safety limits.
A single target with “when I receive a -> broadcast b” and “when I receive b -> broadcast a” appends threads indefinitely inside one live-array sweep. Budget and maximum-sweep checks occur outside that loop.
Evidence: src/platformer/lab/core/runtime.ts:428-444 and 1004-1019. Stage calls step synchronously, so a non-returning step blocks UI handling too.
Proof: independently reran actual Runtime code bundled in memory with existing esbuild. With opBudget=1 and an external guard, result was:
{"guard":"diagnostic guard","broadcastsInOneTick":1001,"configuredBudget":1,"tick":0,"threads":1001}
The unlimited version was deliberately not run in a browser.
Scope: S-M, one core runtime owner. Bound work within live-thread iteration while preserving broadcast ordering and correctly resuming deferred work.
Acceptance: cyclic broadcasts return control, UI and Stop remain responsive, normal messages retain order. This is more serious than the already-known general script-budget performance concern.
Related behavior: Stop All clears current threads, but subsequent physics hooks can create new land/bump/leave-ground scripts. Explorer diagnostic: stopped at y=15; after ten steps y=10 and land counter increased once. See runtime.ts:243-257,457; core/index.ts:35; platformer.ts:303-361. Define automatic-event behavior after Stop All before changing it; retain intended explicit key/click restart behavior.

2. MUST within recovery: make downloaded backups restorable through My projects.
Hackable accepts 5 MiB save envelopes (core/save.ts:32-33), but unified My projects import rejects text above 3,000,000 characters before examining project kind (src/projects/projectFile.ts:20,85-86). Hackable export has no corresponding smaller cap (studio/persist/projectIo.ts:36-50). The cloud saver even recommends a file for oversized projects.
Proof: code-confirmed contract mismatch, not a large real-project browser round-trip.
Scope: S, coordinated save/import contract. Align file limits, account limits and useful messages; do not merely inflate every limit.
Acceptance: a valid project above 3 MB exports, imports through My projects and reopens identically. Local, account and file boundaries should have explicit distinct limits where necessary.

3. MUST within recovery: rebuild orphaned local-project entries.
Hackable writes project text and its listing index separately (persist/hackableProjects.ts:106-115). Index corruption returns an empty list without scanning saved payloads (:59-66,80-92). StudioApp.tsx:77-80 rejects a direct draft URL if it is absent from the index, even if the payload survives.
Proof: explorer used the actual exported functions with isolated in-memory Storage. Successful payload write followed by failed index write left the project stored, returned a storage error and listed no project.
Scope: S-M, same owner as save/recovery. Recover index entries or direct draft payloads safely; never silently discard a recoverable project.
Acceptance: force index-write failure/corruption, reopen and recover the exact project. Existing damaged-index tests do not prove recovery.

4. SHOULD: shared powers must include nested custom-block dependencies.
makePower discovers procedure calls only from the selected scripts, adds those definitions and stops (powers/powers.ts:277-288). Script -> custom block A -> custom block B therefore exports script+A without B. Runtime treats the missing B call as a silent no-op (core/runtime.ts:959-965). Both a power file and the class shelf transport this same incomplete power.
Proof: actual pure makePower function executed in memory returned block IDs ["script","A"], omitting B.
Scope: S, recursive dependency closure with visited-set handling; keep dependency variables/credits intact.
Acceptance: make -> export/share -> import/snap -> play in a different project behaves like the original. Include mutual recursion so dependency collection cannot itself loop.

5. SHOULD: finish the submit -> approve -> use class-shelf journey.
Teacher Shelf loads only on mount/class change (src/pages/class/ShelfTab.tsx:57-66); its successful screen has no refresh or polling. Student picker loads when opened or after that student shares (powers/useClassShelf.ts:36-51). A teacher who opened Shelf before submissions never sees them arrive without leaving/reopening; an already-open student picker never sees an approval.
Proof: code-confirmed, not a three-identity live journey.
Scope: S, teacher/power UI owners. Explicit refresh plus modest visible-only polling can be enough; preserve current selection/Peek.
Also cancel/reject stale responses on session/class changes: useClassShelf.ts:36-45 can let a delayed old-account request repopulate names/descriptions after sign-out. This is a stale-display race, not a demonstrated backend authorization bypass. Existing Worker membership/review/ownership checks looked sound.
Acceptance: three local identities submit, approve and snap without browser reload/tab cycling; delayed account A response cannot appear after switching to B.

6. IF TIME: bound image-cache lifetime and cancel late audio.
