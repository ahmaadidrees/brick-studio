## Done

- `src/pages/join/JoinPage.tsx` replaces the lane stub. One page, one scroll container, three modes from `?mode=`
  (`join` by default, `signin`, `teacher`), `?classCode=` prefill and a `?next=` redirect.
  - **join**: class code first (from the link or the remembered class), class name as a chip once
    `client.classRoster` answers — the code input then collapses behind "Change class code"; live username checklist
    (3–24 · letters, numbers, _ or - · starts with a letter or number · no spaces) and password checklist
    (≥6 · different from your username · not an easy-to-guess password) that go green/red per rule as the student
    types; `username_taken` suggestions as tap-to-fill chips; "Create account and join" is disabled until every rule
    is green, the code is filled and the teacher-facing name is typed.
  - **signin**: username + password only. "I have a class code" reveals the code field, which resolves to the class
    name and the tap-your-name grid (56px tiles, display name with the username under it, 3 columns ≥900px, 2 below).
    Tapping a name fills the username, moves focus to the password and relabels it "Ben K., type your password".
    `class_code_required` opens the code field with its explanation and focuses it. A remembered class is greeted with
    the chip and "Not you? Change class", which calls `forgetClass()`.
  - **teacher**: "Continue with Google" through `client.startGoogleTeacher('/join?mode=teacher…')`, with email and
    password behind a disclosure.
  - Everywhere: "Keep building as a guest" → `/build`, the corner link ("I already have an account" on join,
    "Sign in with username instead" on teacher, "New here? Join a class" on sign-in), and `resetRequired` renders the
    existing `PasswordResetView` inline instead of navigating.
  - After success: `rememberClass`, then `?next=` when it is a same-app path, else `/worlds` for students and
    `/class` for teachers. A `next` pointing off-site is dropped, not followed.
- `joinQuery.ts` (query + destination), `joinRules.ts` (per-rule checklists; the "easy to guess" rule defers to
  `studentPasswordError` so the common-password list stays in one place), `join.css`.
- Entry logic is reused, not rewritten: `client.login/authenticate/classRoster/changePassword/startGoogleTeacher`,
  `panelShared` validation, `rememberedClass`, `PasswordField`, `fields.TextInput`, `RecoveryViews`.
- Tests: `JoinPage.test.tsx` (18) + `joinQuery.test.ts` (6), all three modes, checklist transitions, suggestions,
  enrollment closed, `class_code_required`, wrong password, roster tap and focus, remembered class, `next` redirect
  and the off-site `next`, guest link, inline reset. Driven through the real `ClassroomClient` over a fake `fetch`.
- Screenshots + capture script under `docs/flows/qa/w3/` (see the README there). Dev server ran on 5250 `--strictPort`

## Decisions worth a look

- **Header**: `src/shell/AppHeader.tsx` does not exist in this tree, so the page has a minimal local header
  (`BrandLockup` left, corner link right, one `.join-header` rule). Swap it for `AppHeader variant="page"` when W2
  lands; only `JoinPage.tsx` and two CSS rules change.
- **Corner link copy**: the sheet names "I already have an account" (join) and "Sign in with username instead"
  (teacher). Sign-in had no label, so it reads "New here? Join a class". Change it if the sheet says otherwise.
- **Class lookup**: both modes use the public `POST /auth/roster` (one code path; it returns the class name and
  `canEnroll` as well as the names). `/auth/class` is no longer called from this page. The join form never renders
  the names.
- **Phone password position**: the contract asks for the password in the top half at 390×844. As captured it sits at
  ~60% in sign-in and ~75% in join, because the code field, the class chip and the roster come first. To get there I
  collapse the code input once the class resolves and cap the roster at two rows (scrollable) under 700px; tapping a
  name also focuses the password, which scrolls it up. Tell me if you want the roster moved below the credentials
  instead — that would put the password at ~40% and break the read order.
- **CSS**: the page imports `src/classroom/classroom.css` (unmodified) because `PasswordField` and `TextInput` carry
  `classroom-*` classes. If W2/W6 ever move those primitives into `src/ui`, this import goes away.
- `html, body, #root` are `overflow: hidden` in `styles.css` (the editor needs it), so `.join-page` is its own scroll
  container — the same thing the landing page does.
