## Decisions worth a look

- **No `AppHeader` yet.** W2 had not landed `src/shell/**` when this lane ran, so
  `src/pages/class/ClassPageHeader.tsx` is a minimal local header (brand lockup → Home, "Open the studio",
  account chip with initial, name and "Teacher"). Replacing it with `<AppHeader variant="page" />` is a
  one-line change in `ClassPage.tsx` and `ProjectorPage.tsx`; the file can then be deleted.
- **No `mockClient.ts` yet.** `src/pages/class/demoData.ts` answers the same paths with the flows v2 shapes
  and is used only in dev (`/class?demo=first-run`, `/class?demo=everyday`) and in the screenshots. Delete it
  when W1's mock lands and point `resolveClient()` at that instead.
- **Flows v2 fields are optional locally.** `ClassPageClass` / `ClassPageWorld` in `classPageData.ts` extend
  the current contracts with `studentsCanShare`, `ownerName`, `visibility`, `canEdit`, `sharedAt`,
  `hiddenByTeacher`. Once W1 adds them to `src/classroom/contracts.ts` both aliases can go away.
- **Hiding a shared world** calls `PATCH /classroom/worlds/:id/visibility { hiddenByTeacher }` directly
  through `client.request`. Swap to `client.setWorldHidden` when W1 ships it (one line in
  `classPageData.ts`).
- **"Start a shared world" creates an empty world** (`createBrickStudioDocument([])`) because the page has no
  editor document — the copy says so. If the sheet intended "from the build in my studio", that needs the
  editor's document and should move behind a `/build?classroom=…` intent.

## Requests for the lead

1. **`RosterView` `⋯` menu.** The sheet asks for a `⋯` menu holding Manage / Suspend / Reactivate; the shared
   `RosterSection` renders "Edit student" + "Reset password" buttons instead. I reused it as-is rather than
   edit `src/classroom/**`. The exact change, if you want it: in `src/classroom/RosterView.tsx`,
   `RosterSection` takes an optional `actions?: 'buttons' | 'menu'` (default `'buttons'`) and, for `'menu'`,
   renders one `iconOnly` `⋯` Button with `aria-label={`Manage ${student.rosterName}`}` opening a menu whose
   items call the existing `onManage(student)` and `onManage(student, 'password')` plus a new
   `onToggleSuspend(student)` prop. Nothing else about the component changes.
2. **Class link for a shared personal world.** The contract keeps `class_id` null on personal worlds, so the
   page cannot tell which class a shared student world belongs to when a teacher has two classes; it
   currently shows worlds with `classId === null` under whichever class is selected. Please have W1 return
   the owner's `classId` (or a `sharedClassId`) on shared worlds in `GET /classroom/worlds`.
3. **"N building now" has no source.** No endpoint reports presence, so the chip renders only when a class
   carries an optional `buildingNow` number (the dev fixtures set it, the real API does not). Either add a
   count to `classView` or drop the chip from the sheet.
4. **`studentsCanShare` PATCH is not implemented server-side yet** (W1 owns it). The Settings switch sends
   `{ studentsCanShare: boolean }` to `PATCH /classroom/classes/:id` and will start working when W1 lands;
   until then the worker ignores the key.
