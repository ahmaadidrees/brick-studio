## Requests for lead

1. **Import safeguard (board 12 "Open this build?")**: `useBrickStudioDocuments.importProject` and the cloud
   `onNewBuild` path still use `window.confirm`. Suggested: expose a `confirmReplace(file)` hook or let the
   caller pass a `confirm: (message) => Promise<boolean>` so W4 can show a `Dialog` with "Download current
   build" + "Open build". Same for the `classroom-recovery` bar's `window.confirm` in `BrickStudioApp.tsx`.
2. **Live `onApply` rejection message** (`LiveWorldPage.tsx` `contentPolicy.onApply`): it returns `false` and
   toasts; if W5 wants the inline message in rooms too, widen `contentPolicy.onApply` to return the same
   `{ ok: false, message }` union (lead-owned `BrickStudioAppProps.contentPolicy`).
3. **D9 root cause**: the worker answers 401 for unknown ids and classroom worlds alike. A distinct 404 for
   unknown ids (`liveWorldGateway` / worker) would let the gate say "room not found" instead of the hedged
   copy.
4. **W8 locators** — final accessible names: brand home link `Brickgineers Home` (matches `/Brickgineers/`);
   buttons `Scene`, `Character`, `Settings`, `Explore mode` (visible "Explore") / `Back to building`; People is
   `Build together` outside a room and `People, N here` / `People, N last seen` inside one; world-title menu
   trigger `World menu`; save chip is `role="status"` with `data-kind` = local/cloud/live and `data-tone`;
   Explore HUD region `Explore toolbar`; brick drawer sheet dialog `Bricks`; Settings close `Close settings`.
5. `SaveStatus` primitive: consider exposing an `aria-label`/`labelledBy` prop so tests and W8 can address the
   chip by name rather than `data-kind`.
