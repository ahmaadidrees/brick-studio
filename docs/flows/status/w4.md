## Requests for the lead

1. **`/build?world=<id>` open contract (blocking for the links to work).** Every Open / Join / Visit on this page
   links to `/build?world=<id>` (`buildHref` in `worldsData.ts`). The editor needs to: load that account world and
   attach it as the active world (the `onOpenWorld(document, world)` path `ClassroomPanel` already uses); for a
   classmate's shared personal world, join its live room as a viewer when the caller's `canEdit` is false and as an
   editor when it is true; and, when the id is unknown, hidden or no longer shared, show a plain message with a link
   back to `/worlds` instead of an empty studio. Signed-out visitors on that URL should land on
   `/join?mode=signin&next=/build?world=<id>`. If the lead prefers a different parameter name, say so and I will
   change one constant.
2. **`classCanEdit` on the world payload.** The contract's `canEdit` is caller-scoped, so an owner always sees
   `true` and cannot be told apart from a world shared for building. The page reads `classCanEdit`
   (= `brick_worlds.class_can_edit`) for the owner's chip and the share sheet's preselected option, falling back to
   `canEdit` for a non-owner. Please add it to `GET /classroom/worlds` and to `ClassroomWorld`.
3. **Owner's class on a shared personal world.** Shared personal worlds arrive with `classId: null`, so a teacher
   with more than one class cannot be shown which class a student world belongs to; the page currently lists every
   shared personal world under each class section. An `ownerClassId` (or reusing `classId` on the read model) fixes it.
4. **Teacher name for the closed-collaboration line.** The approved copy is "<Teacher> closed collaboration…"; no
   class payload carries a teacher display name, so the page says "Your teacher closed collaboration. Class worlds
   come back when it reopens." Add `teacherName` to `classView`/`GET /classroom/classes` if the named version is wanted.
5. **Visit counts.** The card shows "· N visits" beside the sharing chip when a world carries `visits`. Nothing in
   the contract produces that number yet — either add it to the worlds read model or tell me to drop the chip.
6. **W2 header.** `src/shell/AppHeader.tsx` does not exist yet, so `src/pages/worlds/PageHeader.tsx` is a local
   header with the same contract (brand lockup home link, "Open the studio", account chip with the account menu).
   Delete it and swap in `AppHeader variant="page"` plus `useClassroomSession()` when W2 lands; the page passes only
   the session and a sign-out callback.
7. **W1 mock client.** `src/pages/worlds/worldsFixtures.ts` is a stand-in for `src/classroom/mockClient.ts` with the
   fixture set the contract lists. When W1 lands, the fake can be replaced by importing the mock client —
   `WorldsClient` in `worldsData.ts` is the only seam.
8. **Live-room read-only state.** "Visit" relies on the live HUD's existing `permission.canEdit` rendering. Worth a
   pass from W6/W7 that a viewer who cannot edit sees that state on arrival rather than failing edits.
