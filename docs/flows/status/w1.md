## Migration text and ordering (lead must read before applying)

`supabase/migrations/202609190001_brick_class_sharing.sql`:
- `brick_worlds`: `class_visibility text not null default 'private'` + check (`private`,`class`), `class_can_edit boolean not null default false`,
  `hidden_by_teacher boolean not null default false`, **plus `class_shared_at timestamptz`** (not in the contract's column list; it backs
  the contract's `sharedAt` because `updated_at` moves on every save — strike it and I will derive `sharedAt` as null if you prefer),
  partial index `brick_worlds_shared_idx` on shared personal worlds. `brick_classes.students_can_share boolean not null default true`.
  All `add column if not exists`.
- `create or replace` of `brick_commit_world` (0002) and `brick_authorize_world` (0005): both selected/checked world columns
  explicitly and rejected every personal world for non-owners. `brick_authorize_world_batch` is unchanged (calls by name).
- **Order: migration before Worker deploy.** The Worker does not tolerate the columns' absence: `GET worlds`, `GET worlds/:id`,
  sharing/visibility/copy select the new columns explicitly (PostgREST 400 → 502 `service_unavailable`), and live join/commit rely
  on the replaced RPCs. The old Worker keeps working after the migration (defaults make every existing world private), so the
  safe sequence is migrate, verify, deploy.
- Behaviour change worth knowing: the owner may now open their own personal world live (before, `/worlds/:id` for a personal
  world was `private_world` even for the owner). Cloud autosave `PUT` and live commits share the revision CAS, so an owner
  saving through autosave while a classmate edits live gets `revision_conflict`; pages should open a shared world through
  the live path (W4/W6).

## Endpoint summary for the page lanes

- `ClassroomWorld`: `visibility`, `canEdit` (caller), `classCanEdit` (owner's setting), `ownerName`, `ownerClassId`, `sharedAt`,
  `hiddenByTeacher?` (teachers). `ClassroomClass`: `studentsCanShare`, `buildingNow: number | null`, `teacherName: string | null`.
- `buildingNow` is real for a teacher's `GET classes` / `GET me` (one internal `GET /internal/classroom-presence` per live-capable
  world of the class, capped at 150 rooms per listing, distinct user ids); `null` at sign-in, for students, beyond the cap or when a
  room fails. The mock returns 3 for Period 3 to the teacher.
- `teacherName` is `null` from the Worker: teacher accounts are bare `auth.users` ids, no roster name exists in the brick tables.
  Cheapest real source would be a `brick_classes.teacher_name` column filled from the Google profile at teacher sign-in; not done
  (contract says nothing renamed/added there). The mock returns "Mr. Idrees".
- Class PATCH accepts `studentsCanShare` (and `showNamesOnJoin` as before); turning sharing off re-authorizes every live room of the
  class including shared personal rooms (classmates are closed, owners stay).
- Live join stays at `/live/<id without dashes>`: `/worlds/:id`, `/worlds/:id/connect?ticket=` and `live-ticket` all go through
  `worldAccess` / `brick_authorize_world`; viewers get `canEdit: false` in `x-classroom-access` (test in `classroomRoutes.test.ts`).
- Errors: 403 `sharing_disabled`, `world_hidden`, `read_only`, `owner_required`, `student_required`, `teacher_required`; 409 `world_limit`.
- Live access `classId` is now `string | null` (null for personal worlds).
